# 游戏开发需求词 · 写作指南

> 给谁看：新机器上的会话。用户会给你一款经典游戏 + 简要资料，你按本指南产出一份「开发需求词」，
> 交给 `threejs-game-director` 去开发。风格范本见 `../garden-autochess-glm/DEVELOPMENT.md`
> 以及本仓库历史三份需求词：`../iron-bastion-1985-glm/DEVELOPMENT.md`（坦克）/ `../mighty-brawl-93-glm/DEVELOPMENT.md`（格斗）/ `../burning-saboteur-87-glm/DEVELOPMENT.md`（潜行）。

## 一、每份需求词的固定结构（按顺序，五段）

1. **工具选择前言**（逐字复用，绑定 `../AGENTS.md`）
2. **技能 + 目录隔离约束**
3. **开发要求**
4. **实现内容**（概念 / 操作 / 内容规模 / 核心系统 / 中文显示 / 画面）
5. **技术与验收**

下面逐段给模板和约定。

## 二、逐段模板

### 1. 工具选择前言（逐字照抄）

```text
先按 AGENTS.md 判断本任务需要 Playwright、Midscene.js、Chrome DevTools MCP 中的哪些工具；只使用
必要工具，并说明选择和跳过原因。诊断后必须回到确定性测试复验。
```

### 2. 技能与目录隔离约束

```text
使用 threejs-game-director 技能，在当前项目目录中新建一个空子目录 {代号}-{年份}-glm，所有新文件
和操作必须限制在该子目录内，不得修改、覆盖或删除当前项目已有内容。
```

约定：

- 目录名用 **ASCII**（中文路径会让部分工具链出问题）：`{代号}-{原作首发年份}-glm`。
- 代号取与玩法/主题相关、但不撞商标的词。例：坦克→`iron-bastion`、格斗→`mighty-brawl`、潜行→`silent-saboteur`、花园自走棋→`garden-autochess`。
- `-glm` 后缀是本项目的命名约定，保留。

### 3. 开发要求（按品类微调）

```text
创建一个可玩的高品质 Three.js 单网页游戏，并由 threejs-game-director 自动调用需要的玩法、图形、UI、
（音频）、调试和 QA 技能，完成设计、开发、性能检查、桌面/移动端适配及全流程验证。不要只做静态场景或
简单 Demo，必须具备完整的开始、游玩、胜负、重开和 {关卡/区域/波次} 推进闭环。
```

- 动作类加「音频」技能；纯策略/自走棋类可省。
- 闭环里的词按品类换：动作/冒险→「关卡」、潜行→「区域」、自走棋/塔防→「波次」。

### 4. 实现内容

由这几个子块拼成：

**(a) 概念句**（致敬 ≠ 复制，必须原创主题）

```text
制作一款致敬《{原作}》{玩法类型}、但完全原创主题与美术的 3D {视角}游戏。主题为「{原创主题}」，
不得直接使用《{原作}》的名字、角色和美术。
```

- 视角：动作类用「斜俯视/俯视」；2D 网格类（自走棋/塔防）用「俯视/斜俯视棋盘」。

**(b) 操作**（键鼠 + 快捷键 + 触控，三件套缺一不可）

```text
- WASD / 方向键：移动
- J / X：{普攻}
- K / C：{跳跃}
- L / V：{必杀技}
- E / 空格：{互动/抓取}
- 支持手机触控（虚拟摇杆 + 按钮）
```

- 快捷键给「主键 / 副键」两组（J/X、K/C、L/V、E/空格）方便不同习惯。
- 策略类没有实时操作时，换成「鼠标拖拽 / 快捷键 R L 1-5 空格 / 触控按钮」。

**(c) 内容规模**（给具体数字，不要“若干”）

- 至少 3 张布局/路线/难度明显不同的 {地图/关卡/区域}；
- 约 N 种植物/武器/角色；
- 约 M 种敌人 + 3 个 BOSS；
- 单局时长（动作类 15~30 分一关、自走棋 12~18 分一局）。

**(d) 核心系统**

血量、命数、计分、暂停、失败重开、通关演出 —— 这些每份都要；再加该品类的**特色系统**：

| 品类 | 特色系统（举例） |
|------|----------------|
| 坦克守卫 | 基地防御、增益道具 |
| 清版格斗 | 连段出招、经验升级解锁招、怒气必杀 |
| 潜行谍报 | 警戒状态机（潜伏→通缉→搜查→恢复）、分级钥匙卡解谜、纸箱躲藏 |
| 自走棋 | 商店刷新/锁定、相邻联动、升星、嫁接/变异构筑、遗物 |

**(e) 中文显示要求**（逐字复用，每份必须有）

```text
游戏内所有文字必须统一使用简体中文显示，包括：标题、主菜单/设置、HUD（{列举该游戏 HUD 项}）、
{商店/道具} 说明、按键提示、暂停/失败/胜利/通关结算界面。中文字符须使用支持中文的字体，避免方块或
乱码；移动端文案不得溢出或被遮挡。
```

**(f) 画面**

```text
画面需有统一 {美术方向} 、卡通 Q版模型、清晰 HUD、{VFX 列举}、音效与 BGM，以及良好的 {手感/反馈}。
```

### 5. 技术与验收（骨架逐字复用，确定性钩子按玩法改）

```text
使用 Three.js + TypeScript + Vite。提供确定性测试钩子（{按玩法写：固定 seed 可复现 X}）、
运行诊断、生产构建、Playwright 交互测试、桌面与移动端视觉基线、画布非空检查和机器人游玩测试（{按玩法
写断言目标}）。Playwright/视觉基线需专门校验中文文案正确渲染、无乱码、无溢出遮挡。最终必须实际运行并
修复发现的问题，交付 README、质量报告、验证命令与结果。未经确认不要 push、创建 PR 或修改父目录。
```

确定性钩子按玩法换：

- 动作/冒险：固定 seed 可复现关卡布局、敌人刷新与战斗结算。
- 潜行：固定 seed 可复现敌人巡逻路线与视线锥。
- 自走棋/塔防：固定商店随机种子可复现摆阵与自动战斗结算，断言经济/升星/联动数值。

## 三、写作约定（必须遵守）

- **致敬 ≠ 复制**：必须写「原创主题/美术，不得直接使用原作名字/角色/商标」。
- **目录名 ASCII**：`{代号}-{年份}-glm`，不用中文目录名。
- **操作三件套**：键鼠 + 快捷键 + 触控，缺一不可。
- **全程简体中文**（含 HUD/菜单/结算），字体防乱码，移动端不溢出。
- **确定性钩子贴合玩法**（见上）。
- **QA 三件套照搬**：Playwright 硬门禁 + 中文渲染校验 + 画布非空/机器人游玩。
- **边界**：未经确认不 push、不建 PR、不改父目录、不动其它游戏子目录。
