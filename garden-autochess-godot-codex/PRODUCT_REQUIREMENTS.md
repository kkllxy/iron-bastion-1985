# 末日花园自走棋（Godot 版）产品需求

> 本文是本次 Godot 新项目实际采用的产品需求词与验收口径，来源于 `garden-autochess-glm/DEVELOPMENT.md` 的目标并结合原创性、Godot/Web 和确定性 QA 约束整理；它不是开发环境假设。实际实现与验证差异记录在 `QUALITY_REPORT.md`。

## 1. 产品目标

制作一款可完整游玩的原创中文 2D 斜俯视花园构筑自走棋。玩家在污染末日中购买和培育变异植物，通过五条横向路线的站位、相邻联动、升星与嫁接抵挡污染怪物。

游戏借鉴“横向分路防守”和“摆阵构筑自动结算”的玩法结构，但不得使用《植物大战僵尸》或其他作品的名称、角色、模型、贴图、音频和受保护美术。全部植物、怪物、世界观、名称和程序化图形必须原创。

首版必须是有开始、每波循环、失败重开和通关演出的完整产品闭环，不接受静态场景或只有单波的技术演示。

## 2. 平台与体验目标

- 平台：macOS 原生可运行；提供 Web 导出配置并面向桌面和移动浏览器适配。
- 界面语言：所有玩家可见文字统一使用简体中文。
- 单局目标：15 波，正常游玩约 12～18 分钟；测试模式允许加速。
- 输入：鼠标、键盘和触控均能完成完整游戏闭环。
- 视觉：统一的“温暖花园生命力 × 冷色污染废土”卡通风格，单位轮廓、阵营和战场层次清晰。

## 3. 核心游戏循环

每波按以下状态顺序运行：

1. 商店/备战：随机出现 5 个种子槽；玩家可购买、刷新、锁定和出售。
2. 摆阵：将库存植物拖入 5×7 草坪网格，或调整已上阵植物的位置。
3. 合成：三株同类同星级植物自动升一星；满足配方的两种植物可嫁接为新品种。
4. 自动战斗：怪物沿五条路线从右向左推进；植物自动索敌、攻击、产能、减速、治疗或阻挡。
5. 奖励：战斗胜利后从 3 个肥料/天气/遗物/变异奖励中选择 1 个，再进入下一波。

第 15 波获胜进入通关结算；任一怪物突破并将花园防线生命降至 0 时进入失败结算。结算页必须提供重开。

## 4. 战场与规则

- 5 条横向路线，每路 7 个可放置格。
- 植物只攻击自身路线，除非能力明确允许跨路、范围或支援。
- 怪物按速度向防线移动，接近阻挡型植物时停下攻击。
- 防线拥有独立生命值；怪物突破时造成伤害后离场。
- 战斗期间阵容锁定，玩家只可使用两个主动工具：铲子和肥料。
- 战斗逻辑使用固定步长，不能依赖渲染帧率。

## 5. 经济、商店与库存

- 货币名为“阳光”，使用整数存储。
- 开局提供可购买首批植物的阳光。
- 植物购买价格由稀有度/强度决定；出售价格必须低于购买价格。
- 商店默认 5 槽；刷新消耗阳光；锁定后跨波保留当前商品。
- 快捷键：`1`～`5` 购买对应槽，`R` 刷新，`L` 锁定。
- 阳光来源包括开局资金、胜利奖励、产能植物、部分联动和遗物。
- UI 只能发出交易请求；经济控制器验证余额后才能变更阳光。

## 6. 植物内容（首版 12 种）

基础与嫁接品种应覆盖以下角色；最终中文名称可以微调，但机制不可缺失：

| 植物 | 定位 | 核心能力 |
| --- | --- | --- |
| 晨露芽 | 产能 | 周期产生阳光 |
| 火绒花 | 远程输出 | 单体火焰伤害 |
| 霜铃草 | 控制 | 伤害并减速 |
| 铁壳果 | 防御 | 高生命并阻挡怪物 |
| 荆棘藤 | 反伤 | 与前方防御植物联动 |
| 月影菇 | 攻速 | 蘑菇网络共享攻速 |
| 蜜灯花 | 辅助 | 治疗/增益相邻植物 |
| 雷荚草 | 爆发 | 连锁或跨目标伤害 |
| 酸囊苔 | 持续伤害 | 施加污染腐蚀 |
| 风扇叶 | 范围 | 推迟或击退同路敌人 |
| 蒸汽莲 | 火×冰嫁接 | 蒸汽范围攻击 |
| 日蚀菇 | 产能×蘑菇嫁接 | 阳光与攻速复合支援 |

三株同类、同星级植物合并为高一星植物，最高三星。三星植物触发两种变异方向二选一，必须改变行为或构筑方向，而不只是线性加数值。

## 7. 相邻联动与嫁接

至少实现并在 HUD 中明确反馈以下联动：

- 晨露芽相邻攻击植物：攻击有概率或按次数附带阳光产出。
- 火绒花相邻霜铃草：解锁蒸汽嫁接或获得蒸汽伤害加成。
- 三株月影菇形成包围/连通关系：建立菌丝网络并共享攻速。
- 荆棘藤位于铁壳果后方：铁壳果受击时反伤。
- 三星植物：弹出两个变异方向供玩家选择。

相邻关系只在布阵改变时重新计算，不在每帧扫描整个棋盘。

## 8. 敌人与 BOSS

普通敌人约 8 种，覆盖：基础、快速、高生命、护甲、远程、分裂、治疗/增益、潜行或抗性。每种必须在轮廓、颜色或特效上可识别。

3 个 BOSS 分别在中期和后期出现，建议节奏为第 5、10、15 波：

- 污泥巨像：高生命、周期护盾或重击。
- 风暴拾荒者：跨路干扰或召唤小怪。
- 腐化园丁：最终 BOSS，具备阶段切换和污染区域能力。

BOSS 不得只是放大版普通敌人；至少有一个改变站位或构筑判断的独特机制。

## 9. 波次、难度与奖励

- 共 15 波，敌人数量、种类、生命、速度和组合逐步升级。
- 固定 seed 下，商店序列、奖励候选、敌人生成与战斗结果必须可复现。
- 每波胜利奖励基础阳光并进入三选一。
- 奖励池至少包含：
  - 肥料：单波或永久属性强化。
  - 天气：影响下一波全场规则，如酸雨、晴空、寒潮。
  - 遗物：提供整局构筑被动。
  - 变异：改变特定植物或元素机制。
- HUD 显示当前天气、遗物、波次、敌人剩余数、关卡进度与得分。

## 10. 主动操作

- 铲子（`Q`）：备战时出售/移除植物；战斗时只能移除或按设计限制使用，必须避免误触。
- 肥料（`E`）：战斗中选择一株植物，给予有限时长的攻速/伤害强化；有清晰冷却和视觉反馈。
- 空格：在备战完成后开始当前波。
- `Esc`：暂停/继续；暂停菜单在游戏树暂停后仍可交互。

触控端提供底部大按钮组和直接拖放，交互目标不小于 44～48 像素，并考虑手指遮挡。

## 11. 中文 UI 与流程页面

必须包含：

- 标题/开始页与简短玩法说明。
- 主 HUD：阳光、波次、防线生命、得分、敌人剩余、天气、遗物和当前阶段。
- 商店：5 个商品槽、价格、定位、购买、刷新、锁定状态。
- 库存与草坪拖放、合法/非法放置反馈、合成提示。
- 奖励三选一与三星变异二选一。
- 暂停、失败、通关和重新开始。
- 桌面快捷键提示与移动端按钮。

中文不得出现方块、乱码、截断、重叠或被移动端安全区域遮挡。重要状态不能只靠颜色表达。

## 12. 美术、动效与音频

- 采用原创程序化 2D 图形、渐变、轮廓和粒子，或使用明确可分发的项目内素材。
- 植物偏暖色与高饱和，污染怪物偏冷青/紫；同路线目标和攻击轨迹清晰。
- 必须有：攻击命中特效、合成光效、升星反馈、阳光拾取、怪物死亡、Boss 登场和通关演出。
- 需要基础音效与循环 BGM；若使用程序化音频，必须避免突兀峰值并提供静音控制。
- 概念图只用于方向参考，不直接复制受保护角色或构图。

## 13. 确定性测试接口

开发构建必须提供可自动化控制的测试接口：

- 设置/读取随机 seed。
- 进入指定波次、备战、战斗、奖励、失败和通关状态。
- 查询阳光、波次、防线生命、得分、棋盘、库存、商店、联动和单位数量。
- 触发购买、刷新、锁定、放置、合成、嫁接、开始战斗、选择奖励和重开。
- 测试加速倍率，仅在测试/调试路径启用。

机器人测试需用固定 seed 跑通至少一局完整 15 波流程，并断言：

- 购买与刷新正确扣费，锁定正确保留商品。
- 三合一升星发生且单位数量/星级正确。
- 至少两种相邻联动产生可观测数值变化。
- 至少一种嫁接和一种三星变异成功。
- 波次、奖励、防线、得分、失败/重开和通关状态正确。

## 14. 发布硬门禁

- Godot 项目无脚本解析错误，可无头启动并正常退出。
- 固定 seed 逻辑测试全部通过。
- Web 导出成功后，Playwright 桌面与移动 viewport 的核心流程、中文文案和 Canvas 非空检查通过。
- 机器人完整局测试通过。
- 视觉基线覆盖开始、备战、战斗、奖励、失败/通关的关键场景。
- Midscene（若可用）只补充视觉语义结论；不能替代上述确定性门禁。
- 若发现 Console、网络或性能异常，使用 DevTools 定位后必须回到确定性测试复验。
